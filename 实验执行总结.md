# 当前 Prefix / Calibration 协议（本轮）

ANN-training 与 post-finetuning conversion calibration 已严格分离。共享目录 `_shared/seed42/rotated_prefix/` 仅保存 rotation、ANN-training Prefix 和 ANN-training calibration；其中 calibration 仅供 phase-aware / gif-aware ANN 微调使用。`vanilla_original/vanilla_analysis_calibration` 只做原始坐标统计分析，禁止用于 conversion。

每个 `ann_mode/lr.../seed.../ann/final` 训练完成后，必须依次运行：

```bash
python scripts/discover_prefix.py --config "$CFG" --stage post_finetuning
python scripts/calibrate_sites.py --config "$CFG" --stage post_finetuning
```

这会生成 run-specific 的 `post_finetuning/prefix` 与 `post_finetuning/conversion_calibration/sites`。Final ANN evaluation 和所有 SNN evaluation 都使用该 Prefix；SNN conversion 只接受 purpose 为 `post_finetuning_conversion_calibration`、且 `eligible_for_conversion=true` 的 calibration。Vanilla 的训练无 rotation、无 Prefix、无 replacement，但它的 final ANN/SNN pipeline 同样使用 post-finetuning Prefix 与 calibration。

# 实验执行总结

以下命令只说明运行顺序，不代表已经执行实验。所有命令都从项目根目录 `SNN/` 运行。环境安装见 `环境配置.md`。

## 1. 生成12个 ANN 配置

```bash
python scripts/materialize_configs.py
```

输出位于 `configs/generated/`：

```text

exp1_qwen3_8b_tldr__{vanilla,unaware,phase_aware,gif_aware}.yaml
exp2_llama3_8b_tulu3__{vanilla,unaware,phase_aware,gif_aware}.yaml
```

## 2. 数据 manifest

同一任务只需生成一次；TL;DR 的两个模型共用 raw-sample manifest。

```bash
python scripts/prepare_data.py --config configs/generated/exp1_qwen3_1_7b_tldr__unaware.yaml
python scripts/prepare_data.py --config configs/generated/exp2_llama3_8b_tulu3__unaware.yaml
```

TL;DR 保存完整 train、完整 validation、test manifest 以及从 train 无放回抽取的128条 calibration manifest。Tulu 3 保存 seed42 无放回的100k train、其外1000条 validation，以及从100k train 无放回抽取的128条 calibration；抽中的 calibration 样本继续保留在训练集。

## 3. 每个模型准备 rotation、prefix 与两套 calibration

对每个 model-task pair，rotated 三种设置共用一套状态；Vanilla 单独生成原坐标状态。下面以 Qwen3-1.7B 为例：

```bash
ROT_CFG=configs/generated/exp1_qwen3_1_7b_tldr__unaware.yaml
VAN_CFG=configs/generated/exp1_qwen3_1_7b_tldr__vanilla.yaml

python scripts/prepare_rotation.py --config "$ROT_CFG"
python scripts/discover_prefix.py --config "$ROT_CFG"
python scripts/calibrate_sites.py --config "$ROT_CFG"
python scripts/calibrate_sites.py --config "$VAN_CFG"


ROT_CFG=configs/generated/exp1_qwen3_8b_tldr__unaware.yaml
VAN_CFG=configs/generated/exp1_qwen3_8b_tldr__vanilla.yaml
python scripts/prepare_rotation.py --config "$ROT_CFG"
python scripts/discover_prefix.py --config "$ROT_CFG"
python scripts/calibrate_sites.py --config "$ROT_CFG"
python scripts/calibrate_sites.py --config "$VAN_CFG"


ROT_CFG=configs/generated/exp2_llama3_8b_tulu3__unaware.yaml
VAN_CFG=configs/generated/exp2_llama3_8b_tulu3__vanilla.yaml
python scripts/prepare_rotation.py --config "$ROT_CFG"
python scripts/discover_prefix.py --config "$ROT_CFG"
python scripts/calibrate_sites.py --config "$ROT_CFG"
python scripts/calibrate_sites.py --config "$VAN_CFG"
```

把前缀替换为 `exp1_qwen3_8b_tldr` 和 `exp2_llama3_8b_tulu3`，分别执行同样四条命令。`prepare_rotation.py` 保存的是 fused Base checkpoint；后续微调直接优化其中的融合后权重。

如果 calibration/prefix discovery 需要2、3或4张卡做模型切分，可在单进程命令前限制相应 GPU，配置中的 `device_map: auto` 会使用所有可见设备：

```bash
CUDA_VISIBLE_DEVICES=0,1 python scripts/calibrate_sites.py --config "$ROT_CFG"
CUDA_VISIBLE_DEVICES=0,1,2 python scripts/calibrate_sites.py --config "$ROT_CFG"
CUDA_VISIBLE_DEVICES=0,1,2,3 python scripts/calibrate_sites.py --config "$ROT_CFG"
```

不要用多个进程同时写同一套 shared calibration。

## 6. 创建36个 SNN conversion descriptor

对每个 ANN config 分别运行三种 neuron：

```bash
CFG=configs/generated/exp1_qwen3_1_7b_tldr__phase_aware.yaml
for NEURON in phase gif mtn; do
  python scripts/convert_snn.py --config "$CFG" --neuron "$NEURON"
done
```

对12个 config 全部执行，即得到 `12 × 3 = 36` 个 conversion descriptor。转换只加载微调前 frozen calibration state，不执行 post-fine-tuning recalibration。

## 8. 校验工件

每个 config 完成 conversion/evaluation 后运行：

```bash
python scripts/verify_artifacts.py \
  --config configs/generated/exp1_qwen3_1_7b_tldr__phase_aware.yaml
```

校验内容包括：数据 manifest、`ann/final` 最终 ANN checkpoint、每层十个 calibration site、三种 conversion metadata 和相应评测结果。

每层固定收集 10 个 activation replacement site；新增 Site 9 位于 MLP up_proj 后，原 R4 后 product site 顺延为 Site 10。

## 9. 日志与失败恢复

每一步都会生成：

```text
logs/<stage>[_rankN].log
logs/<stage>[_rankN].jsonl
logs/<stage>[_rankN]_result.json
```

result JSON 记录状态、开始/结束时间、wall-clock、rank/world size、每张可见 GPU 的峰值显存、GPU 型号和软件版本。训练恢复只允许显式设置生成 config 中的 `training.resume_from_checkpoint`；不得因 OOM 静默改变 micro-batch、gradient accumulation、eager attention 或 gradient checkpointing。
