# 实验执行总结

本文是当前项目唯一的实验执行顺序说明。路径示例沿用项目既有拼写：启用 Prefix 的目录名为 `prefix_enabled_ture`，关闭时为 `prefix_enabled_false`。

# 第一部分：实验执行命令总结

## Step 1：配置四个 Prefix 开关并生成配置

四个开关分别控制四类实际执行阶段：

```yaml
ann_training:
  prefix_enabled: true              # ANN training 及 ANN-training calibration

rotated_pre_finetuning:
  prefix_enabled: true              # Rotation 后、ANN 微调前 evaluation

post_finetuning:
  prefix_enabled: true              # Post-finetuning conversion calibration 与 SNN conversion

evaluation:
  prefix_enabled: true              # Final ANN checkpoint evaluation 与 SNN evaluation
```

所有值都只能写 YAML 布尔值 `true` 或 `false`。原有 `prefix.enabled` 仅作为旧配置兼容字段；新实验以以上四个 `prefix_enabled` 为准。Vanilla 的 ANN training 始终不使用 Prefix。

先在 `configs/experiment_matrix.yaml` 中设置默认值或 mode override，再生成 12 个配置：

```bash
cd /home/wangwenkang/SNN

python scripts/materialize_configs.py \
  --matrix configs/experiment_matrix.yaml \
  --output-dir configs/generated
```

如需只改变某次运行，可在生成后修改对应 YAML。改变任一开关不会覆盖另一种开关取值的结果，因为相关输出目录均带 `prefix_enabled_ture` 或 `prefix_enabled_false`。

以下命令使用这些变量：

```bash
CFG_17_V=configs/generated/exp1_qwen3_1_7b_tldr__vanilla.yaml
CFG_17_U=configs/generated/exp1_qwen3_1_7b_tldr__unaware.yaml
CFG_17_P=configs/generated/exp1_qwen3_1_7b_tldr__phase_aware.yaml
CFG_17_G=configs/generated/exp1_qwen3_1_7b_tldr__gif_aware.yaml

CFG_8_V=configs/generated/exp1_qwen3_8b_tldr__vanilla.yaml
CFG_8_U=configs/generated/exp1_qwen3_8b_tldr__unaware.yaml
CFG_8_P=configs/generated/exp1_qwen3_8b_tldr__phase_aware.yaml
CFG_8_G=configs/generated/exp1_qwen3_8b_tldr__gif_aware.yaml

CFG_L_V=configs/generated/exp2_llama3_8b_tulu3__vanilla.yaml
CFG_L_U=configs/generated/exp2_llama3_8b_tulu3__unaware.yaml
CFG_L_P=configs/generated/exp2_llama3_8b_tulu3__phase_aware.yaml
CFG_L_G=configs/generated/exp2_llama3_8b_tulu3__gif_aware.yaml

TLDR_CFGS=("$CFG_17_V" "$CFG_17_U" "$CFG_17_P" "$CFG_17_G" \
           "$CFG_8_V"  "$CFG_8_U"  "$CFG_8_P"  "$CFG_8_G")
TULU_CFGS=("$CFG_L_V" "$CFG_L_U" "$CFG_L_P" "$CFG_L_G")
ALL_CFGS=("${TLDR_CFGS[@]}" "${TULU_CFGS[@]}")
```

## Step 2：准备固定数据 manifest

TL;DR 的 manifest 在同一 task/seed 下共享，只需用一个 TL;DR 配置生成一次；Tulu 3 同理：

```bash
python scripts/prepare_data.py --config "$CFG_17_V"
python scripts/prepare_data.py --config "$CFG_L_V"
```

`training.tldr_train_samples` 为整数时，ANN training 会严格按 `training.tldr_train_seed` 固定、随机、无放回选取该数量的训练样本；为 `null` 时使用完整 train split。

## Step 3：Base baseline 评估

Base baseline 必须使用 vanilla config、`--base --neuron ann`，不加载 Rotation、Prefix 或 calibration。

TL;DR：

```bash
CUDA_VISIBLE_DEVICES=0 accelerate launch --num_processes 1 \
  scripts/evaluate_tldr.py --config "$CFG_17_V" --neuron ann --base

CUDA_VISIBLE_DEVICES=0 accelerate launch --num_processes 1 \
  scripts/evaluate_tldr.py --config "$CFG_8_V" --neuron ann --base
```

Tulu 3 / lm-eval：

```bash
CUDA_VISIBLE_DEVICES=0 accelerate launch --num_processes 1 \
  scripts/evaluate_lm_harness.py --config "$CFG_L_V" --neuron ann --base
```

## Step 4：准备 Rotation，并可选执行 ANN 微调前评估

每个 model-task pair 只准备一次 Rotation：

```bash
for CFG in "$CFG_17_U" "$CFG_8_U" "$CFG_L_U"; do
  python scripts/prepare_rotation.py --config "$CFG"
done
```

微调前 Prefix 是一个共享对象。只要 `ann_training.prefix_enabled=true` 或 `rotated_pre_finetuning.prefix_enabled=true`，就在 Rotation 完成后发现一次：

```bash
for CFG in "$CFG_17_U" "$CFG_8_U" "$CFG_L_U"; do
  python scripts/discover_prefix.py \
    --config "$CFG" \
    --stage pre_finetuning
done
```

可选的 Rotation 后、ANN 微调前 evaluation 在 ANN training 之前执行。是否使用共享 Prefix 由 `rotated_pre_finetuning.prefix_enabled` 决定。

TL;DR：

```bash
CUDA_VISIBLE_DEVICES=0 accelerate launch --num_processes 1 \
  scripts/evaluate_tldr.py \
  --config "$CFG_17_U" --neuron ann --rotated-pre-finetuning

CUDA_VISIBLE_DEVICES=0 accelerate launch --num_processes 1 \
  scripts/evaluate_tldr.py \
  --config "$CFG_8_U" --neuron ann --rotated-pre-finetuning
```

Tulu 3 / lm-eval：

```bash
CUDA_VISIBLE_DEVICES=0 accelerate launch --num_processes 1 \
  scripts/evaluate_lm_harness.py \
  --config "$CFG_L_U" --neuron ann --rotated-pre-finetuning
```

## Step 5：生成 ANN-training calibration

每个 rotated model 的 ANN-training calibration 在训练前生成。它是否使用共享的微调前 Prefix，由 `ann_training.prefix_enabled` 决定：

```bash
for CFG in "$CFG_17_U" "$CFG_8_U" "$CFG_L_U"; do
  python scripts/calibrate_sites.py \
    --config "$CFG" \
    --stage ann_training
done
```

Vanilla analysis calibration 不使用 Prefix，只用于原始 Vanilla activation 的分析，不作为 rotated ANN training 或 SNN conversion 的 calibration：

```bash
for CFG in "$CFG_17_V" "$CFG_8_V" "$CFG_L_V"; do
  python scripts/calibrate_sites.py \
    --config "$CFG" \
    --stage vanilla_analysis
done
```

当同一 model-task pair 的 unaware、phase-aware、gif-aware 使用相同 `ann_training.prefix_enabled` 时，Rotation、微调前 Prefix 和 ANN-training calibration 都是共享工件，各生成一次即可。若比较 `true` 与 `false`，分别用对应配置生成两套 ANN-training calibration。

## Step 6：训练 12 个 ANN checkpoint

示例使用两张 GPU。每个配置的训练根目录包含 `ann_training.prefix_enabled` 对应后缀：

```bash
export CUDA_VISIBLE_DEVICES=0,1
NGPU=2

for CFG in "${ALL_CFGS[@]}"; do
  torchrun \
    --standalone \
    --nproc_per_node="$NGPU" \
    scripts/train_ann.py \
    --config "$CFG"
done
```

对于 TL;DR，启动后应看到类似 `Tokenizing SNN2 training dataset (1024 samples)`。训练步数应由实际选中的样本数、GPU 数、batch size、gradient accumulation 和 epoch 共同决定。

## Step 7：为每个 final ANN checkpoint 生成 Post-finetuning Prefix

Post-finetuning Prefix 来自各自的 final ANN checkpoint，因此 12 个 run 必须分别发现。只要 `post_finetuning.prefix_enabled=true` 或 `evaluation.prefix_enabled=true`，就执行：

```bash
for CFG in "${ALL_CFGS[@]}"; do
  python scripts/discover_prefix.py \
    --config "$CFG" \
    --stage post_finetuning
done
```

如果两个开关都为 `false`，本步骤可以跳过。

## Step 8：生成 Post-finetuning conversion calibration

每个 final ANN checkpoint 都独立重新 calibration。是否在 calibration forward 中加载 Post-finetuning Prefix，由 `post_finetuning.prefix_enabled` 决定：

```bash
for CFG in "${ALL_CFGS[@]}"; do
  python scripts/calibrate_sites.py \
    --config "$CFG" \
    --stage post_finetuning
done
```

这套 calibration 是后续 SNN conversion 使用的唯一 calibration，不能用 ANN-training calibration 替代。

## Step 9：评估 12 个 final ANN checkpoint

是否使用 Post-finetuning Prefix 由 `evaluation.prefix_enabled` 决定，结果目录按该值隔离。

TL;DR：

```bash
export CUDA_VISIBLE_DEVICES=0

for CFG in "${TLDR_CFGS[@]}"; do
  accelerate launch --num_processes 1 \
    scripts/evaluate_tldr.py \
    --config "$CFG" \
    --neuron ann
done
```

Tulu 3 / lm-eval：

```bash
for CFG in "${TULU_CFGS[@]}"; do
  accelerate launch --num_processes 1 \
    scripts/evaluate_lm_harness.py \
    --config "$CFG" \
    --neuron ann
done
```

## Step 10：创建 SNN conversion descriptor 并执行 SNN evaluation

Conversion 使用 Step 8 中由 `post_finetuning.prefix_enabled` 指定的 calibration。每个 run 分别创建 phase、gif、mtn 三种 descriptor：

```bash
for CFG in "${ALL_CFGS[@]}"; do
  for NEURON in phase gif mtn; do
    python scripts/convert_snn.py \
      --config "$CFG" \
      --neuron "$NEURON"
  done
done
```

SNN evaluation 自身是否加载 Post-finetuning Prefix，由 `evaluation.prefix_enabled` 决定。

TL;DR：

# 第二部分：附录

## 附录 A：整体依赖顺序

实验依赖关系是：

```text
固定数据 manifest
├── Base baseline（无 Rotation / Prefix / calibration）
└── Rotation
    ├── 共享的 Pre-finetuning Prefix
    │   ├── 可选的 rotated pre-finetuning evaluation
    │   └── ANN-training calibration
    └── ANN training
        └── final ANN checkpoint
            ├── Post-finetuning Prefix
            ├── Post-finetuning conversion calibration
            │   └── SNN conversion descriptor
            └── final ANN / SNN evaluation
```

Base baseline 被放在数据 manifest 之后、所有 Rotation/Prefix/calibration 操作之前，是为了明确它只衡量原始 pretrained Base。Rotation 后、ANN 微调前 evaluation 紧随 Rotation 和共享 Prefix 的准备，用于隔离观察 Rotation 与 Prefix 本身的影响。

## 附录 B：四个 `prefix_enabled` 的边界

| 配置键 | 控制对象 | Prefix 来源 | 影响的输出路径 |
|---|---|---|---|
| `ann_training.prefix_enabled` | ANN training；ANN-training calibration | Pre-finetuning Prefix | run 根目录；ANN-training calibration |
| `rotated_pre_finetuning.prefix_enabled` | Rotation 后、ANN 微调前 evaluation | Pre-finetuning Prefix | rotated pre-finetuning evaluation |
| `post_finetuning.prefix_enabled` | Post-finetuning conversion calibration；SNN conversion descriptor | Post-finetuning Prefix | conversion calibration；conversion descriptor |
| `evaluation.prefix_enabled` | final ANN evaluation；SNN evaluation | Post-finetuning Prefix | final ANN/SNN evaluation |

这些开关彼此独立。例如：

- `post_finetuning.prefix_enabled=false`、`evaluation.prefix_enabled=true`：conversion calibration 不带 Prefix，但 final ANN/SNN evaluation 带 Prefix。
- `ann_training.prefix_enabled=false`、`rotated_pre_finetuning.prefix_enabled=true`：ANN training/calibration 不带 Prefix，但微调前评估使用同一个 Pre-finetuning Prefix。
- `evaluation.prefix_enabled=false` 时，评估代码忽略已有 Prefix 工件，并把结果写入 `prefix_enabled_false`。

目录中的 `prefix_enabled_ture` 是项目已有且需保持兼容的拼写，不应手工改成 `prefix_enabled_true`。

## 附录 C：两类 Prefix 的定义与生成时间

### C.1 Pre-finetuning Prefix

Pre-finetuning Prefix 在 Rotation 完成后，从 rotated fused Base 上发现。它同时服务于：

- ANN training；
- ANN-training calibration；
- Rotation 后、ANN 微调前 evaluation。

旧实现中的 `ann_training_prefix` 和 `rotated_pre_finetuning/prefix` 实际来源相同，现在已经合并为同一个对象：

```text
.../_shared/seed42/rotated_prefix/pre_finetuning_prefix/
├── prefix_state.json
└── prefixed_key_values.pt    # prefix_token_ids 非空时存在
```

发现命令统一为：

```bash
python scripts/discover_prefix.py --config CONFIG --stage pre_finetuning
```

`--stage ann_training` 与 `--stage rotated_pre_finetuning` 仍作为兼容别名接受，但都会写入同一 canonical 目录；新实验只使用 `--stage pre_finetuning`。

### C.2 Post-finetuning Prefix

Post-finetuning Prefix 在 ANN training 完成后，从每个 run 自己的 `ann/final` 重新发现。它服务于：

- Post-finetuning conversion calibration；
- final ANN checkpoint evaluation；
- SNN evaluation。

因为不同 ann_mode、学习率、训练样本数和 ANN-training Prefix 设置会产生不同 final checkpoint，所以 Post-finetuning Prefix 不跨 run 共享。

`prefix_state.json` 中：

- `prefix_token_ids` 是实际 Prefix token ID；
- `prefix_text` 是 tokenizer 对这些 ID 的 decode 结果；
- `prefix_token_ids: [29038]` 且 `prefix_text: "SUB"` 表示该 tokenizer 将 token 29038 decode 为 `SUB`；
- 非空 Prefix 还要求存在固定的 `prefixed_key_values.pt`。

## 附录 D：三类 Calibration 的定义与生成时间

### D.1 Vanilla analysis calibration

来源是原始 pretrained Base，不带 Rotation 和 Prefix。它只用于观察 Vanilla activation 统计，不可用于 ANN training 或 SNN conversion。

生成时间：固定数据 manifest 之后即可。

### D.2 ANN-training calibration

来源是 rotated fused Base，生成时间在 ANN training 之前。它由 `ann_training.prefix_enabled` 决定 calibration forward 是否加载 Pre-finetuning Prefix。

- `true`：读取共享 Pre-finetuning Prefix；
- `false`：完全不读取 Prefix state/KV；
- 两种结果进入不同的 `prefix_enabled_*` 目录。

phase-aware 和 gif-aware ANN training 从与自身开关相符的 calibration 目录读取 replacement site states。

### D.3 Post-finetuning conversion calibration

来源是每个 run 的 final ANN checkpoint，生成时间在训练完成和 Post-finetuning Prefix 发现之后、SNN conversion 之前。它由 `post_finetuning.prefix_enabled` 决定是否加载 Post-finetuning Prefix。

该 calibration 包含 final ANN checkpoint、固定 calibration manifest、Rotation、Prefix 开关与 Prefix 文件 hash 等 provenance，是 phase/gif/mtn conversion 共同使用的 run-specific calibration。

## 附录 E：各步骤的输入、输出和结果含义

### E.1 固定数据 manifest

典型输出：

```text
artifacts/<experiment>/<task>/_shared/seed42/data/
├── train_manifest.json
├── validation_manifest.json
├── evaluation_manifest.json
└── calibration_manifest.json
```

TL;DR 的 train manifest 可以记录完整 split，但 ANN training 会再次按照当前配置的 `tldr_train_samples` 和 seed 构造严格匹配的训练子集，因此修改为 1024 后实际 tokenization 和训练都只能看到 1024 个训练样本。

### E.2 Base baseline

```text
.../<model>/base/seed42/evaluation/
├── tldr/<test_samples_dir>/metrics.json
└── lm_harness/results.json
```

该目录不带 `prefix_enabled_*`，因为 Base baseline 明确不允许 Prefix。

### E.3 Rotation 和共享 Pre-finetuning Prefix

```text
.../<model>/_shared/seed42/rotated_prefix/
├── rotation/
│   ├── fused_base/
│   └── rotation_state.pt
└── pre_finetuning_prefix/
    ├── prefix_state.json
    └── prefixed_key_values.pt
```

Rotation 后、ANN 微调前 evaluation 输出：

```text
.../rotated_prefix/rotated_pre_finetuning/evaluation/
├── tldr/<test_samples_dir>/prefix_enabled_ture|prefix_enabled_false/
└── lm_harness/prefix_enabled_ture|prefix_enabled_false/
```

### E.4 ANN-training calibration

```text
.../<model>/_shared/seed42/rotated_prefix/ann_training_calibration/
└── prefix_enabled_ture|prefix_enabled_false/
    └── sites/
        ├── calibration_state_manifest.json
        └── layer_*/site_*/
```

manifest 中的 `prefix_enabled` 和 `prefix_protocol_enabled` 必须与目录后缀一致。

### E.5 ANN training

TL;DR run 根目录示意：

```text
.../<model>/<ann_mode>/
└── lr<lr>_train_samples_<full-or-N>/
    └── prefix_enabled_ture|prefix_enabled_false/
        └── seed42/
            └── ann/
                ├── final/
                ├── trainer/
                ├── tokenization_metadata.json
                └── training_result.json
```

Tulu 3 省略 `_train_samples_<...>`，其余结构一致。这里的 Prefix 后缀对应 `ann_training.prefix_enabled`，不是最终评估开关。

`tokenization_metadata.json` 中的 `configured_tldr_train_samples`、`actual_train_samples` 与 `training_result.json` 中的 `train_samples` 可用于确认实际训练样本数。

### E.6 Post-finetuning Prefix 与 conversion calibration

```text
.../<run>/post_finetuning/
├── prefix/
│   ├── prefix_state.json
│   └── prefixed_key_values.pt
└── conversion_calibration/
    └── prefix_enabled_ture|prefix_enabled_false/
        └── sites/
            └── calibration_state_manifest.json
```

Post-finetuning Prefix 对象本身只保存一份；是否在 conversion calibration 中使用它由 calibration 目录后缀表达。

SNN conversion descriptor：

```text
.../<run>/snn/<phase|gif|mtn>/conversion/
└── prefix_enabled_ture|prefix_enabled_false/
    └── conversion_metadata.json
```

该后缀对应 `post_finetuning.prefix_enabled`。

### E.7 Final ANN 与 SNN evaluation

TL;DR final ANN：

```text
.../<run>/ann/evaluation/tldr/<test_samples_dir>/
└── prefix_enabled_ture|prefix_enabled_false/
    ├── predictions.jsonl
    ├── selection.json
    └── metrics.json
```

TL;DR SNN：

```text
.../<run>/snn/<neuron>/evaluation/tldr/<test_samples_dir>/
└── prefix_enabled_ture|prefix_enabled_false/
    ├── predictions.jsonl
    ├── selection.json
    └── metrics.json
```

lm-eval 对应输出：

```text
.../<run>/ann/evaluation/lm_harness/prefix_enabled_ture|prefix_enabled_false/results.json
.../<run>/snn/<neuron>/evaluation/lm_harness/prefix_enabled_ture|prefix_enabled_false/results.json
```

这些评估后缀统一对应 `evaluation.prefix_enabled`。结果 metadata 同时记录 `prefix_enabled`、`prefix_stage`、模型来源和 calibration 来源，便于区分同一 checkpoint 的带 Prefix/不带 Prefix 结果。

## 附录 F：逐点命令说明

- `prepare_data.py`：固定 train、validation、evaluation 和 128 条 calibration 样本的索引。
- `prepare_rotation.py`：生成 fused Base、Rotation state 和 regression 信息；不生成 Prefix。
- `discover_prefix.py --stage pre_finetuning`：从 rotated fused Base 发现唯一的共享微调前 Prefix。
- `evaluate_* --rotated-pre-finetuning`：加载 rotated fused Base；只读取 `rotated_pre_finetuning.prefix_enabled`。
- `calibrate_sites.py --stage ann_training`：读取 `ann_training.prefix_enabled`，为 ANN replacement-aware training 准备 states。
- `train_ann.py`：读取 `ann_training.prefix_enabled`，全参数训练并保存 canonical `ann/final`。
- `discover_prefix.py --stage post_finetuning`：从当前 run 的 `ann/final` 重新发现 Post-finetuning Prefix。
- `calibrate_sites.py --stage post_finetuning`：读取 `post_finetuning.prefix_enabled`，生成 conversion-only calibration。
- `evaluate_tldr.py` / `evaluate_lm_harness.py`：普通 final ANN/SNN 评估只读取 `evaluation.prefix_enabled`；`--base` 永远无 Prefix。
- `convert_snn.py`：读取 `post_finetuning.prefix_enabled` 对应的 calibration，创建冻结的 full-temporal SNN descriptor。
