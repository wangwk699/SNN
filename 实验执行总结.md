# 实验执行总结

本文是当前项目唯一的实验执行顺序说明。路径示例沿用项目既有拼写：启用 Prefix 的目录名为 `prefix_enabled_ture`，关闭时为 `prefix_enabled_false`。

# 第一部分：实验执行命令总结

## Step 1：配置四个 Prefix 开关并生成配置

四个开关分别控制四类实际执行阶段：

```yaml
rotated_pre_finetuning:
  prefix_enabled: true              # Rotation 后、ANN 微调前 evaluation

ann_training:
  prefix_enabled: true              # ANN training 及 ANN-training calibration

post_finetuning:
  prefix_enabled: true              # Post-finetuning conversion calibration 与 SNN conversion

evaluation:
  prefix_enabled: true              # Final ANN checkpoint evaluation 与 SNN evaluation

replacement:
  common_clip_enabled: true         # 仅控制 aware ANN replacement 后是否执行 common Clip
```

所有值都只能写 YAML 布尔值 `true` 或 `false`。矩阵提供共享默认值，resolved config 会按 mode 强制协议：vanilla 的 Pre-finetuning/ANN-training Prefix 关闭，aware 的 Post-finetuning Prefix 与 calibration 关闭。原有 `prefix.enabled` 仅作为旧配置兼容字段；新实验以以上四个 `prefix_enabled` 为准。Base baseline 与 vanilla ANN training 均不使用 Prefix。

`replacement.common_clip_enabled` 只控制 `phase_aware` / `gif_aware` ANN fine-tuning 是否在 Phase/GIF replacement 后执行 common Clip。ANN-training calibration 无论该值为 true 或 false 都生成 `clip_state.pt`；所有 SNN conversion/deployment 都不执行 common Clip。vanilla/unaware resolved config 会将该值固定为 false。

`configs/experiment_matrix.yaml` 现在只有一个 `experiments` 列表；每个 model-task 条目直接保存完整配置和四种 `ann_modes`，不存在 `defaults`、`model_runs` 或 `mode_overrides` 的合并。用它一次性生成 12 个配置：

```bash
cd /home/wangwenkang/SNN

python scripts/materialize_configs.py \
  --matrix configs/experiment_matrix.yaml \
  --output-dir configs/generated
```

`configs/generated/` 继续由 Git 忽略，测试也会在临时目录调用同一个 materializer，不依赖仓库内预生成文件。生成后不应手工漂移 temporal/GIF 策略；如需调整实验规模，应修改矩阵并重新 materialize。当前 TL;DR 训练固定为 `training.tldr_train_samples: 10000`，Qwen3-1.7B 的快速评估保留 `evaluation.tldr_test_samples: 128`，Qwen3-8B 按 resolved config 使用完整 test split；Tulu 3 设置 `data.train_size: null`，lm-eval 设置 `evaluation.limit: null`。改变任一 Prefix 开关不会覆盖另一种取值的结果，因为相关输出目录均带 `prefix_enabled_ture` 或 `prefix_enabled_false`。

以下命令使用这些变量：

```bash
CFG_17_V=configs/generated/exp1_qwen3_1_7b_tldr__vanilla.yaml
CFG_17_U=configs/generated/exp1_qwen3_1_7b_tldr__unaware.yaml
CFG_17_P=configs/generated/exp1_qwen3_1_7b_tldr__phase_aware.yaml
CFG_17_G=configs/generated/exp1_qwen3_1_7b_tldr__gif_aware.yaml

CFG_8_V=configs/generated/exp1_qwen3_8b_tldr__vanilla.yaml
CFG_8_U=configs/generated/exp1_qwen3_8b_tldr__unaware.yaml
CFG_8_P=configs/generated/exp1_qwen3_8b_tldr__phase_aware.yaml
CFG_8_G=configs/generated/exp1_qwen3_8b_tldr__gif_aware.yaml

CFG_L_V=configs/generated/exp2_llama3_8b_tulu3__vanilla.yaml
CFG_L_U=configs/generated/exp2_llama3_8b_tulu3__unaware.yaml
CFG_L_P=configs/generated/exp2_llama3_8b_tulu3__phase_aware.yaml
CFG_L_G=configs/generated/exp2_llama3_8b_tulu3__gif_aware.yaml

TLDR_CFGS=("$CFG_17_V" "$CFG_17_U" "$CFG_17_P" "$CFG_17_G" \
           "$CFG_8_V"  "$CFG_8_U"  "$CFG_8_P"  "$CFG_8_G")
TULU_CFGS=("$CFG_L_V" "$CFG_L_U" "$CFG_L_P" "$CFG_L_G")
```


## Step 5：生成 ANN-training calibration

ANN-training calibration 只为 phase-aware/gif-aware 在训练前生成；同一模型任务的两个 aware mode 复用 rotated fused Base 的 Pre-finetuning Prefix 与同一 calibration。vanilla/unaware 不运行该 stage。

ANN-training calibration 基于训练前 ANN 的 site statistics 生成 Phase、GIF、MTN 参数以及 neuron-independent common clipping interval。其中 `clip_state.pt` 仅供 `phase_aware` / `gif_aware` ANN fine-tuning 使用：

```bash
for CFG in "$CFG_17_P" "$CFG_8_P" "$CFG_L_P"; do
  python scripts/calibrate_sites.py \
    --config "$CFG" \
    --stage ann_training
done
```

Vanilla analysis calibration 不使用 Prefix，只用于原始 Vanilla activation 的分析，不作为 rotated ANN training 或 SNN conversion 的 calibration：

```bash
for CFG in "$CFG_17_V" "$CFG_8_V" "$CFG_L_V"; do
  python scripts/calibrate_sites.py \
    --config "$CFG" \
    --stage vanilla_analysis
done
```

同一 model-task pair 的 phase-aware 与 gif-aware 共享 ANN-training calibration；unaware 只依赖 Pre-finetuning Prefix，不依赖该 calibration。

`common_clip_enabled=true/false` 两种 aware training variant 共享完全相同的 Pre-finetuning Prefix 与 ANN-training calibration。只切换该参数不需要重新发现 Prefix 或重新 calibration，前提是其他 calibration 配置、代码版本和 artifact hash 未变化。

## Step 6：训练 12 个 ANN checkpoint

示例使用两张 GPU。每个配置的训练根目录包含 `ann_training.prefix_enabled` 对应后缀：

```bash
export CUDA_VISIBLE_DEVICES=0,1
NGPU=2

for CFG in "${ALL_CFGS[@]}"; do
  torchrun \
    --standalone \
    --nproc_per_node="$NGPU" \
    scripts/train_ann.py \
    --config "$CFG"
done
```

对于 TL;DR 由 `tldr_train_samples` 指定训练样本数量。训练步数应由实际选中的样本数、GPU 数、batch size、gradient accumulation 和 epoch 共同决定。

Aware ANN forward 语义为：`phase_aware + true -> Clip(Phase(x))`、`phase_aware + false -> Phase(x)`、`gif_aware + true -> Clip(GIF(x))`、`gif_aware + false -> GIF(x)`。两种路径仍是局部 replacement 后立即聚合的 ANN fine-tuning，不引入跨层时间维度。

## Step 7：为每个 final ANN checkpoint 生成 Post-finetuning Prefix

Post-finetuning Prefix 只供 `vanilla` 与 `unaware` 的 final ANN checkpoint 使用；`phase_aware` 与 `gif_aware` 必须复用 Pre-finetuning Prefix，且脚本会拒绝其 post_finetuning stage。对 vanilla/unaware，只要 `post_finetuning.prefix_enabled=true` 或 `evaluation.prefix_enabled=true`，就执行：

```bash
for CFG in "$CFG_17_V" "$CFG_17_U" "$CFG_8_V" "$CFG_8_U" "$CFG_L_V" "$CFG_L_U"; do
  python scripts/discover_prefix.py \
    --config "$CFG" \
    --stage post_finetuning
done
```

如果两个开关都为 `false`，本步骤可以跳过。

## Step 8：生成 Post-finetuning conversion calibration

只有 `vanilla` 与 `unaware` 的 final ANN checkpoint 独立重新 calibration；aware 模式会拒绝该 stage，并复用 ANN-training calibration。是否在 calibration forward 中加载 Post-finetuning Prefix，由 `post_finetuning.prefix_enabled` 决定。

该阶段针对每个 final ANN checkpoint 重新统计全部 10 个 site，并生成 `phase_state.pt`、`gif_state.pt`、`mtn_state.pt`；不生成 `clip_state.pt`。Post-finetuning calibration 是供 SNN conversion 使用的 clip-free state bundle，而 ANN-training calibration 为了 `phase_aware` / `gif_aware` ANN 微调仍包含 common Clip：

```bash
for CFG in "$CFG_17_V" "$CFG_17_U" "$CFG_8_V" "$CFG_8_U" "$CFG_L_V" "$CFG_L_U"; do
  python scripts/calibrate_sites.py \
    --config "$CFG" \
    --stage post_finetuning
done
```

对 `vanilla`/`unaware`，这套 calibration 是 conversion 唯一来源；对 `phase_aware`/`gif_aware`，ANN-training calibration 才是唯一来源，且 conversion 会校验训练结果中记录的 Prefix/manifest 哈希。

重新执行该步骤会写入 format v5 的 Phase/GIF/MTN site state、format v6 calibration manifest 与全局 final RMSNorm Phase state。manifest 的 `expected_num_hidden_layers` 来自实际模型 config，实际目录必须完整覆盖 `layer_000..layer_{N-1}`，且每层恰好 10 个 site。重新 materialize 会自动删除旧 `clip_state.pt`；仍含 Clip、使用旧 Phase channel view 或旧 schema 的 Post-finetuning bundle 不能复用。

## Final ANN mode-aware forward 语义

12 个 final checkpoint 的 `--neuron ann` 统一表示 non-temporal final ANN evaluation，但实际 activation forward 由 `ann_mode` 决定：

| `ann_mode` | ANN training | final `--neuron ann` |
|---|---|---|
| `vanilla` | identity | identity |
| `unaware` | identity（保留 Rotation/Prefix） | identity（保留 Rotation/Prefix） |
| `phase_aware` | `PhaseSurrogate.forward()` + optional common Clip | 同一 ANN-training states 与相同 Clip 设置的 `PhaseSurrogate.forward()` |
| `gif_aware` | `StaticGIF.forward()` + optional common Clip | 同一 ANN-training states 与相同 Clip 设置的 `StaticGIF.forward()` |

Aware static surrogate 的时间动态只存在于 site 内并立即聚合，T 不跨 Transformer layer，因此仍属于 ANN。Base 与 rotated-pre-finetuning diagnostic 保持 identity。

## Step 10：创建 SNN conversion descriptor 并执行 SNN evaluation

Step 10 与 Step 9 的 static ANN semantics 不同：无论 checkpoint 的 `ann_mode` 是什么，`--neuron phase|gif|mtn` 都分别进入 `deploy_phase|deploy_gif|deploy_mtn` full-temporal SNN，且不使用 common Clip。

`vanilla` / `unaware` 使用 Step 7 Post-finetuning Prefix 与 Step 8 Post-finetuning conversion calibration；`phase_aware` / `gif_aware` 不执行 Step 7 / Step 8，直接复用 Step 4 Pre-finetuning Prefix 与 Step 5 ANN-training calibration。每个 run 分别创建 phase、gif、mtn 三种 descriptor。

Phase conversion 只读取 Phase state，GIF conversion 只读取 GIF state，MTN conversion 只读取 MTN state。三种 SNN deployment 都不加载或执行任何额外 Clip；GIF `_quantize()` 内部的 `qmin/qmax` clamp 属于 GIF 编码算法自身，必须继续保留：

```bash
for CFG in "${ALL_CFGS[@]}"; do
  for NEURON in phase gif mtn; do
    python scripts/convert_snn.py \
      --config "$CFG" \
      --neuron "$NEURON"
  done
done
```

# 第二部分：附录

## 附录 A：整体依赖顺序

实验依赖关系是：

```text
固定数据 manifest
├── Base baseline（无 Rotation / Prefix / calibration）
├── Vanilla 策略
│   └── ANN training（无 Prefix / replacement）
│       └── final ANN
│           ├── Post-finetuning Prefix
│           ├── Post-finetuning conversion calibration
│           └── conversion / evaluation
├── Unaware 策略
│   └── Rotation
│       ├── 共享 Pre-finetuning Prefix
│       └── ANN training
│           └── final ANN
│               ├── Post-finetuning Prefix
│               ├── Post-finetuning conversion calibration
│               └── conversion / evaluation
└── Aware 策略
    └── Rotation
        ├── 共享 Pre-finetuning Prefix
        ├── 共享 ANN-training calibration
        └── aware ANN training
            └── final ANN
                └── conversion / evaluation（复用训练前 Prefix + calibration）
```

Base baseline 被放在数据 manifest 之后、所有 Rotation/Prefix/calibration 操作之前，是为了明确它只衡量原始 pretrained Base。Rotation 后、ANN 微调前 evaluation 紧随 Rotation 和共享 Prefix 的准备，用于隔离观察 Rotation 与 Prefix 本身的影响。

## 附录 B：四个 `prefix_enabled` 的边界

| 配置键 | 控制对象 | Prefix 来源 | 影响的输出路径 |
|---|---|---|---|
| `ann_training.prefix_enabled` | ANN training；ANN-training calibration | Pre-finetuning Prefix | run 根目录；ANN-training calibration |
| `rotated_pre_finetuning.prefix_enabled` | Rotation 后、ANN 微调前 evaluation | Pre-finetuning Prefix | rotated pre-finetuning evaluation |
| `post_finetuning.prefix_enabled` | 仅 vanilla/unaware 的 Post-finetuning conversion calibration 与 conversion | Post-finetuning Prefix | conversion calibration；conversion descriptor |
| `evaluation.prefix_enabled` | final ANN evaluation；SNN evaluation | aware 为 Pre-finetuning；vanilla/unaware 为 Post-finetuning | final ANN/SNN evaluation |

这些开关受 mode protocol 约束，并非四种 mode 都能自由组合：

| 配置 | vanilla | unaware | phase_aware | gif_aware |
|---|---:|---:|---:|---:|
| `ann_training.prefix_enabled` | 强制 false | 强制 true | 强制 true | 强制 true |
| `rotated_pre_finetuning.prefix_enabled` | 无此流程 | 可独立 true/false | 可独立 true/false | 可独立 true/false |
| `post_finetuning.prefix_enabled` | 可 true/false | 可 true/false | 不使用 | 不使用 |
| `evaluation.prefix_enabled` | 可 true/false | 可 true/false | 可 true/false | 可 true/false |

`ann_training.prefix_enabled` 不是自由 ablation 参数；vanilla 固定为 false，所有 rotated modes 固定为 true。阶段适用范围内的 evaluation / post-finetuning 开关可以独立控制。例如：

- `post_finetuning.prefix_enabled=false`、`evaluation.prefix_enabled=true`：conversion calibration 不带 Prefix，但 final ANN/SNN evaluation 带 Prefix。
- `evaluation.prefix_enabled=false` 时，评估代码忽略已有 Prefix 工件，并把结果写入 `prefix_enabled_false`。

目录中的 `prefix_enabled_ture` 是项目已有且需保持兼容的拼写，不应手工改成 `prefix_enabled_true`。

## 附录 C：两类 Prefix 的定义与生成时间

### C.1 Pre-finetuning Prefix

Pre-finetuning Prefix 只存在于 unaware、phase-aware、gif-aware，在 Rotation 完成后从同一个 rotated fused Base 发现并按 model-task 共享。它服务于：

- ANN training；
- ANN-training calibration；
- Rotation 后、ANN 微调前 evaluation。

旧实现中的 `ann_training_prefix` 和 `rotated_pre_finetuning/prefix` 实际来源相同，现在已经合并为同一个对象。canonical 路径是：

```text
.../_shared/seed42/rotated_prefix/pre_finetuning_prefix/
├── prefix_state.json
└── prefixed_key_values.pt    # prefix_token_ids 非空时存在
```

发现命令统一为：

```bash
python scripts/discover_prefix.py --config CONFIG --stage pre_finetuning
```

`--stage ann_training` 与 `--stage rotated_pre_finetuning` 仍作为兼容别名接受，但都会写入同一 canonical 目录；新实验只使用 `--stage pre_finetuning`。

### C.2 Post-finetuning Prefix

Post-finetuning Prefix 仅为 vanilla/unaware 在 ANN training 完成后从各自 `ann/final` 发现。它服务于：

- Post-finetuning conversion calibration；
- final ANN checkpoint evaluation；
- SNN evaluation。

该 Prefix 不跨 vanilla/unaware run 共享；phase-aware/gif-aware conversion 与 final evaluation 始终复用训练前 Prefix。

`prefix_state.json` 中：

- `prefix_token_ids` 是实际 Prefix token ID；
- `prefix_text` 是 tokenizer 对这些 ID 的 decode 结果；
- `prefix_token_ids: [29038]` 且 `prefix_text: "SUB"` 表示该 tokenizer 将 token 29038 decode 为 `SUB`；
- 非空 Prefix 还要求存在固定的 `prefixed_key_values.pt`。

## 附录 D：三类 Calibration 的定义与生成时间

### D.1 Vanilla analysis calibration

来源是原始 pretrained Base，不带 Rotation 和 Prefix。它只用于观察 Vanilla activation 统计，不可用于 ANN training 或 SNN conversion。

生成时间：固定数据 manifest 之后即可。

### D.2 ANN-training calibration

ANN-training calibration 只用于 phase-aware / gif-aware，生成时间在 ANN training 之前，来源是 rotated fused Base；它由 `ann_training.prefix_enabled` 决定 calibration forward 是否加载共享 Pre-finetuning Prefix。

- `true`：读取共享 Pre-finetuning Prefix；
- `false`：完全不读取 Prefix state/KV；
- 两种结果进入不同的 `prefix_enabled_*` 目录。

phase-aware 和 gif-aware ANN training 从与自身开关相符的 calibration 目录读取 replacement site states。ANN-training calibration 同时生成 neuron-independent common clipping interval；`clip_state.pt` 仅用于 `Phase -> Clip` 和 `GIF -> Clip` 的 ANN fine-tuning 路径。

ANN-training calibration 中的 common Clip 只服务 aware ANN fine-tuning；aware conversion 复用该 bundle 但 controller 不加载 Clip，vanilla/unaware 则使用独立的 clip-free Post-finetuning bundle。

### D.3 Post-finetuning conversion calibration

仅用于 vanilla/unaware，来源是各自 final ANN checkpoint，生成时间在训练完成和 Post-finetuning Prefix 发现之后、SNN conversion 之前。它由 `post_finetuning.prefix_enabled` 决定是否加载 Post-finetuning Prefix。

该 calibration 包含 final ANN checkpoint、固定 calibration manifest、Rotation、Prefix 开关与 Prefix 文件 hash 等 provenance，是 phase/gif/mtn conversion 共同使用的 run-specific calibration。

它生成 Phase、GIF、MTN full-temporal neuron states，不生成 `clip_state.pt`；conversion 要求 `state_profile=snn_conversion_without_clip`、`common_clip_required=false`，发现旧 Clip 文件会直接失败。

## 附录 E：各步骤的输入、输出和结果含义

### E.1 固定数据 manifest

典型输出：

```text
artifacts/<experiment>/<task>/_shared/seed42/data/
├── train_manifest.json
├── validation_manifest.json
├── evaluation_manifest.json
```

## 附录 F：逐点命令说明

- `prepare_data.py`：固定 train、validation、evaluation 和 128 条 calibration 样本的索引。
- `prepare_rotation.py`：生成 fused Base、Rotation state 和 regression 信息；不生成 Prefix。
- `discover_prefix.py --stage pre_finetuning`：unaware 与两个 aware mode 从 rotated fused Base 发现共享 Prefix；vanilla 不执行该步骤。
- `evaluate_* --rotated-pre-finetuning`：加载 rotated fused Base；只读取 `rotated_pre_finetuning.prefix_enabled`。
- `calibrate_sites.py --stage ann_training`：读取 `ann_training.prefix_enabled`，为 ANN replacement-aware training 生成 Phase/GIF/MTN state 和 common `clip_state.pt`。
- `train_ann.py`：读取 `ann_training.prefix_enabled`，全参数训练并保存 canonical `ann/final`。
- `discover_prefix.py --stage post_finetuning`：从当前 run 的 `ann/final` 重新发现 Post-finetuning Prefix。

## 附录 G：Temporal v3、Phase 对齐与重跑边界

Temporal v3 保留 time-major `[T,B,...]`、cross-time QK/PV、cumulative-difference Softmax 和 MLP 主公式；Prefix K/V 在 ANN-aware replacement 与 deployment runtime 中都经过 Site 3/4 neuron，但 calibration statistics 与 saliency 仍排除 Prefix positions。embedding 各帧使用 `x/T`，完整 Softmax（含 Prefix columns）经过 Site 5，仅 `deploy_phase` 在最终 RMSNorm 后执行 global Phase neuron。普通 Phase main experiment固定 `surrogate_slope=1.0`。

Phase τ calibration 不统一把 runtime tensor 最后一维当 channel。attention Site 2/3/4/6 的 Phase statistical view 先展平 attention heads，Site 5 Softmax 则以 head 为 channel；该 reshape 只用于 Phase EMA，generic value/GIF/MTN/Clip statistics 与 runtime neuron layout 不变。每个 Phase channel 独立执行 factor 0.99 的 FP32 EMA，最后跨全部 channel 取 global max 得到 scalar τ。Phase state 的 `group_size` 固定为 `-1`，通用 `calibration.group_size` 不改变普通 Phase baseline 的 τ grouping。

当前 state/manifest/conversion/temporal schema 分别为 v5/v6/v7/v3。manifest 为所有 Phase/GIF/MTN/Clip（若存在）和 global final RMSNorm Phase state 保存 SHA-256。Aware ANN training 在训练前冻结 Prefix state/KV 与 calibration manifest hash，训练结束后再次校验磁盘工件未变化；aware conversion 校验 `training_result` 中记录的冻结 provenance，任何漂移都必须失败。

### 重跑边界

本次变更改变 Phase calibration、Softmax Site 5、embedding temporal encoding、final RMSNorm Phase state 和 conversion provenance，因此旧 conversion calibration 与旧 SNN descriptor/evaluation 不可复用。`phase_aware`/`gif_aware` 的 ANN training forward 所使用的 Phase/GIF state 也发生来源与哈希协议变化：正式结果需要重新生成 Pre-finetuning Prefix 与 ANN-training calibration，并重新运行 aware ANN fine-tuning；随后直接复用这套工件转换，不再运行 aware Post-finetuning Prefix 或 calibration。`vanilla`/`unaware` 可复用语义未变化且来源可证明的 final ANN checkpoint，但必须重新生成 Post-finetuning artifacts、conversion descriptor 与 SNN evaluation。

## 附录 H：Phase Conversion Debug / Regression

`scripts/regress_phase_conversion.py` 只用于 `phase_aware + replacement.common_clip_enabled=false + ann_training.prefix_enabled=true`，比较同一 final checkpoint、Pre-finetuning Prefix 与 ANN-training Phase states 下的 training-time static Phase graph 和 temporal Phase SNN graph。

脚本启动时严格校验：

- final ANN 的 mode/common-Clip 标记；
- training_result 中的 Prefix、calibration manifest 哈希与 common-Clip 应用记录；
- Phase conversion descriptor 的 artifact reuse、无 post-finetuning recalibration 与无 SNN Clip 合同。

历史旧实现中，官方 `evaluate_tldr.py --neuron ann` 对 `phase_aware` 使用 identity controller。本轮修正后，`phase_aware --neuron ann` 正式对齐 Graph P（training-time static Phase graph）；Graph I 只保留为 regression diagnostic baseline。正式 conversion loss 以相同 Prefix、样本和 decode policy 下的 Graph P / `--neuron ann` 与 Graph S / `--neuron phase` 比较。

推荐命令：

```bash
CUDA_VISIBLE_DEVICES=6 \
conda run --no-capture-output -n snn2 python scripts/regress_phase_conversion.py \
  --config <common_clip_false_resolved_config.yaml> \
  --sample-index 0 \
  --max-input-tokens 64 \
  --decode-steps 16
```

输出位于 `<run>/analysis/phase_conversion_regression/`，包括 artifact validation、Phase micro、temporal primitives、四图 fixed-forward、checkpoint metrics、first divergence、final-norm ablation 与 locked-token decode。

当前 Qwen3-1.7B、LR=1e-7 诊断结论：

- 修复前第一个 `>1e-2` 节点为 `layer_000/site_01/post`；
- 对齐 Qwen/Llama BF16 RMSNorm cast 顺序后，Site 1 pre/post 均为零，首点后移到 Site 2；
- 当前首个非零点是 Layer 0 q/k/v projection 的 BF16 分帧线性求和（约 `2.5e-3`），q_norm、RoPE、R3 继续累积后在 Site 2/3 被 Phase 阈值放大；FP32 primitive 未失败，因此没有改动这些算法路径；
- final RMSNorm Phase bypass 未显著缩小 P vs S，因此当前证据不支持先修改 global final Phase topology。

Regression 工具与诊断修正不改变 Phase 参数、τ、Prefix、训练 LR、T、base 或 Site 数量；未被 first-divergence 证实的算子不得为追求 ROUGE 而修改。
