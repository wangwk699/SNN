# 实验执行总结

本文是当前项目唯一的实验执行顺序说明。路径示例沿用项目既有拼写：启用 Prefix 的目录名为 `prefix_enabled_ture`，关闭时为 `prefix_enabled_false`。

# 第一部分：实验执行命令总结

## Step 1：配置 Prefix 开关与 SNN artifact source selector 并生成配置

以下配置项分别控制 Prefix、SNN artifact source 与 common Clip 的实际执行阶段：

```yaml
rotated_pre_finetuning:
  prefix_enabled: true              # Rotation 后、ANN 微调前 evaluation

ann_training:
  prefix_enabled: true              # ANN training 及 ANN-training calibration

post_finetuning:
  prefix_enabled: true              # Post-finetuning conversion calibration 与 SNN conversion

evaluation:
  prefix_enabled: true              # unaware/aware 的 Final ANN checkpoint evaluation 与 SNN evaluation；vanilla 的 Final ANN 固定不加载 Prefix

conversion:
  use_post_finetuning_artifacts: true # 仅选择 SNN conversion/evaluation 的 Prefix + Stage A 来源

replacement:
  common_clip_enabled: true         # 仅控制 aware ANN replacement 后是否执行 common Clip
```

所有值都只能写 YAML 布尔值 `true` 或 `false`。`conversion.use_post_finetuning_artifacts` 只选择 SNN conversion/evaluation 的整套来源：`true` 使用 Step 7/8 的 Post-finetuning Prefix + Stage A，`false` 使用 Step 4/5 的 Pre-finetuning Prefix + ANN-training Stage A；vanilla 只能设为 `true`。该 selector 不改变 ANN training、Final ANN evaluation 或 rotated-pre-finetuning evaluation。原有 `prefix.enabled` 仅作为旧配置兼容字段；Base baseline、vanilla ANN training 与 vanilla final ANN evaluation 均不使用 Prefix。

`replacement.common_clip_enabled` 只控制 `phase_aware` / `gif_aware` ANN fine-tuning 是否应用当前 Stage B Clip profile。Stage A 不生成 `clip_state.pt`；Stage B 在独立 profile 中为 9 个 eligible sites 生成 Clip，Site 5 永久例外。所有 SNN conversion/deployment 都不执行 common Clip。vanilla/unaware resolved config 会将该值固定为 false。

`configs/experiment_matrix.yaml` 现在只有一个 `experiments` 列表；每个 model-task 条目直接保存完整配置和四种 `ann_modes`，不存在 `defaults`、`model_runs` 或 `mode_overrides` 的合并。用它一次性生成 12 个配置：

```bash
cd /home/wangwenkang/SNN

python scripts/materialize_configs.py \
  --matrix configs/experiment_matrix.yaml \
  --output-dir configs/generated
```

`configs/generated/` 继续由 Git 忽略，测试也会在临时目录调用同一个 materializer，不依赖仓库内预生成文件。生成后不应手工漂移 temporal/GIF 策略；如需调整实验规模，应修改矩阵并重新 materialize。当前 TL;DR 训练固定为 `training.tldr_train_samples: 10000`，Qwen3-1.7B 与 Qwen3-8B generated configs 均使用 `evaluation.tldr_test_samples: 1000`；若后续 matrix 设为 `null`，则表示完整 evaluation split。Tulu-3 使用 `training.train_samples: 10000` 与 `training.train_seed: 42`；固定 1000 条 validation 后，从训练池随机无放回取样。lm-eval 由每个 task 的 `enabled`、`num_fewshot`、`cot`、`test_samples`、`test_seed` 控制，`test_samples: null` 表示完整 benchmark。改变任一 Prefix 开关不会覆盖另一种取值的结果，因为相关输出目录均带 `prefix_enabled_ture` 或 `prefix_enabled_false`。

以下命令使用这些变量：

## Step 2：准备固定数据 manifest

TL;DR 与 Tulu-3 的 manifest 只在完整 data-selection identity 相同的配置间共享；该 identity 包含 experiment seed、task-specific training seed、train sample count 与 calibration seed。每一个新的 `train_samples` 值都必须使用对应配置完整执行一次 Step 2：

```bash
python scripts/prepare_data.py --config "$CFG_17_V"
python scripts/prepare_data.py --config "$CFG_L_V"
```

TL;DR `training.tldr_train_samples: null` 表示使用完整 train split。若把它改为整数，ANN training 会严格按 `training.tldr_train_seed` 固定、随机、无放回选取该数量的训练样本，当前默认 TL;DR ANN training 固定使用 10000 个训练样本；Stage-A calibration 再从这批 ANN training samples 内按 `calibration.seed` 随机无放回选取当前 128 条。Tulu-3 的 `training.train_samples: null` 表示使用完整训练池；整数 N 表示先在 `experiment.seed` 固定的、排除 1000 条 validation 的 training pool 中按 `training.train_seed` 随机无放回选取 N 条（当前 10000），Stage-A calibration 再从这批 ANN training samples 内按 `calibration.seed` 随机无放回选取当前 128 条。因此统一关系是：`Stage-A Calibration 128 ⊆ 当前 Step 2 固定的 ANN Training subset`；默认 `train_samples=10000` 时即 `Stage-A Calibration 128 ⊆ ANN Training 10000`，若 `train_samples=N` 则为 `Stage-A Calibration 128 ⊆ ANN Training N`。

项目存在两套不同用途的数据选择。第一套是 **fixed canonical 128**：直接从 raw train 中按 `experiment.seed` 固定、随机、无放回抽取 128 条，用于 Rotation regression 与 Pre-finetuning Prefix discovery；它不依赖 task-specific training seed、`train_samples`、`calibration.seed` 或 `calibration.num_samples`，也不要求属于当前 ANN training subset。第二套是 **Stage-A calibration subset**：先由 Step 2 根据 task-specific training seed 与 `train_samples` 固定 ANN training subset，再从该 subset 内按 `calibration.seed` 抽取 `calibration.num_samples` 条；它用于 ANN-training Stage A/B，并随完整 data-selection identity 改变。

**只要 sweep 的 `train_samples` 改变，都应该把它视为一条新的数据选择 → calibration → training → conversion 实验链。** 对 TL;DR，`train_samples` 指 `training.tldr_train_samples`；对 Tulu-3，指 `training.train_samples`。

所有 ANN training 使用的训练样本集合必须事先通过修改对应 YAML 配置并执行完整 Step 2 `prepare_data.py` 固化到 `train_manifest.json`。Step 6 ANN training 只能消费该 manifest 中的 `indices`，禁止根据 `train_samples`、task-specific training seed 或 `experiment.seed` 在训练阶段重新生成、重采样或替换 training indices。修改 train sample count 或 task-specific training seed 后，禁止直接跳到 Step 6。

Tulu-3 lm-eval 默认任务如下；`cot` 不传给 `simple_evaluate()`，而是对固定 lm-eval revision 的 task prompt variant 做强一致性校验。

| task           | enabled | few-shot |      metric |   CoT | test_samples | test_seed |
| -------------- | ------: | -------: | ----------: | ----: | -----------: | --------: |
| truthfulqa_mc1 |    true |        0 |         acc | false |    null/full |        42 |
| agieval        |    true |        0 |         acc | false |         1000 |        42 |
| arc_challenge  |    true |        0 |    acc_norm | false |    null/full |        42 |
| piqa           |    true |        0 |    acc_norm | false |    null/full |        42 |
| winogrande     |    true |        0 |         acc | false |    null/full |        42 |
| boolq          |    true |        0 |         acc | false |    null/full |        42 |
| mmlu_pro       |   false |        5 | exact_match |  true |    null/full |        42 |
| bbh            |   false |        3 | exact_match |  true |    null/full |        42 |
| gsm8k_cot      |   false |        4 | exact_match |  true |    null/full |        42 |
| minerva_math   |   false |        4 | exact_match | false |    null/full |        42 |

若 training data identity 完全不变，仅需补齐新的 `calibration.num_samples` 对应 calibration manifest（例如 `num_samples_256`），可以使用 `--calibration-only`。该模式只读取已经存在且与当前 YAML 完全匹配的 Step 2 `train_manifest.json`，并从其固定 indices 内抽取 calibration；它不会创建、重建或重新采样 ANN training subset。train manifest 缺失或 sample count/seed 不匹配时必须先完整重跑 Step 2：

```bash
python scripts/prepare_data.py --config "$CFG_17_V" --calibration-only
python scripts/prepare_data.py --config "$CFG_L_V" --calibration-only
```

`train_samples` 改变后的重跑边界：

| Step | 是否重跑 | 原因 |
| --- | --- | --- |
| Step 1 | 是 | 新 sample count 必须进入配置与 artifact identity |
| Step 2 | **必须完整重跑** | 生成新的唯一 training manifest，不能只跑 `--calibration-only` |
| Step 3 Base | 否 | Base 与 training sample count 无关 |
| Step 4 Rotation | **不用** | 使用 fixed canonical 128 |
| Step 4 Pre-finetuning Prefix | **不用** | 使用同一 fixed canonical 128 |
| Step 4 rotated-pre-finetuning eval | **不用** | rotated Base 与 fixed Pre Prefix 均不变 |
| Step 5 Stage A/B | **必须重跑** | Stage-A calibration 改变 |
| Step 5.1 GIF MSE | 启用时必须重跑 | histogram/qparams 依赖 Stage-A calibration |
| Step 6 ANN training | **必须重跑** | training subset 改变 |
| Step 7 Post Prefix | **必须重跑** | final checkpoint 改变 |
| Step 8 Post Stage A | **必须重跑** | checkpoint / calibration 改变 |
| Step 9 Final ANN eval | **必须重跑** | checkpoint 改变 |
| Step 10 SNN conversion/eval | **必须重跑** | run-specific artifacts 改变 |

只改变 `calibration.seed` 时，fixed canonical 128、Rotation、Rotation regression、Pre-finetuning Prefix 与 rotated-pre-finetuning evaluation 全部复用，Stage-A chain 按新 seed 隔离。只改变 `calibration.num_samples`（例如 128/256/512）时同样复用上述共享工件，仅 Stage-A calibration、ANN-training Stage A/B 以及 run-specific Post Prefix/Post Stage A 发生变化。

## Step 5：生成 ANN-training Calibration Stage A/B

ANN-training calibration 在训练前为 phase-aware/gif-aware 生成；同一 model-task、Prefix、`group_size`、`num_samples` 组合共享一个 T/K-independent Stage A。该 Stage A 也作为 unaware/phase-aware/gif-aware 在 `use_post_finetuning_artifacts=false` 时的共享 SNN calibration 来源；unaware 不需要单独重跑 Step 5。每个 `phase.T`/`mtn.T` 组合生成独立 Stage B Clip profile。

```bash
for CFG in "$CFG_17_P" "$CFG_8_P" "$CFG_L_P"; do
  python scripts/calibrate_sites.py \
    --config "$CFG" \
    --stage ann_training \
    --calibration-phase A

  python scripts/calibrate_sites.py \
    --config "$CFG" \
    --stage ann_training \
    --calibration-phase B
done
```

Stage A 生成 statistics 与 Phase/GIF/MTN common states，site 目录内不含 Clip。Stage B 仅读取 Stage A，在 `clip_profiles/phase_T_<P>_mtn_T_<M>/` 下生成 mask-aware、role-aware Clip。只改变 Phase/MTN `T` 时仅重跑 B；改变 `mtn.K` 时 A/B 都不用重跑；改变 `group_size` 或 `num_samples` 时必须重跑 A 与所需 B。

Vanilla analysis 如需执行，只运行 `--stage vanilla_analysis --calibration-phase A`。

### Step 5.1：启动 GIF offline static-MSE qparam 搜索（可选实验分支）

默认配置保持 direct min-max：

```yaml
gif:
  mse_scale_refinement: false
```

要运行 MSE 对照实验，**只对目标 `gif_aware` 配置**建立一个独立副本，并将该项改为 `true`；不要原地覆盖 direct 对照配置。例如 Tulu-3 Llama-3-8B：

```bash
CFG_L_G_DIRECT=configs/generated/exp2_llama3_8b_tulu3__gif_aware.yaml
CFG_L_G_MSE=configs/generated/exp2_llama3_8b_tulu3__gif_aware_mse.yaml

cp "$CFG_L_G_DIRECT" "$CFG_L_G_MSE"
# 在 $CFG_L_G_MSE 中仅修改：gif.mse_scale_refinement: true

python scripts/calibrate_sites.py \
  --config "$CFG_L_G_MSE" \
  --stage ann_training \
  --calibration-phase A
```

不新增 `--mse-refinement` CLI 参数。`mse_scale_refinement: true` 会在上述 Stage A 内部自动运行：Pass 1 保持原有 direct min-max statistics；Pass 2 用相同的 calibration manifest、相同样本顺序和相同 Prefix 收集 GIF fixed-bin histogram；随后自动物化 refined `gif_state.pt`。因此不应先运行一次 direct Stage A、再单独运行“搜索命令”。Post-finetuning MSE calibration 同样只需把 `--stage` 改为 `post_finetuning`：

```bash
python scripts/calibrate_sites.py \
  --config "$CFG_L_G_MSE" \
  --stage post_finetuning \
  --calibration-phase A
```

默认搜索设置位于 `gif.mse_refinement`：4096 bins、coarse asymmetric clipping alpha 列表、fine alpha 邻域、local scale ratio 和 `zero` 邻域。算法按分组分别优化 low（`qmax=15`）与 salient/high（`qmax=30`）qparams；direct min-max 始终保留为候选，最终落盘 FP32 参数会重新核验，若 MSE 没有严格改善则回退 direct。`calibration.group_size` 仍是唯一分组来源，支持 `128`、`64` 与 `-1`。

当 `calibration.gif_previous_layers_snn: false`（默认）时，流程为“全模型 Pass 1 → 全模型 Pass 2 histogram → 全部 GIF state”。当其为 `true` 时，严格按每层执行“statistics → histogram → gif state → temporal deployment → 下一层”。两种模式都保持运行期 static GIF quantization；MSE 只发生在离线 calibration。

MSE artifacts 会额外带 `gif_qparams_mse_refined_v1_<config-hash>` 路径段，因而与 direct、不同 `group_size`、不同 MSE 搜索超参数互不覆盖。完成训练、conversion 与 evaluation 后，可使用完整 artifact verifier：

```bash
conda run -n snn2 python scripts/verify_artifacts.py --config "$CFG_L_G_MSE"
```

对于 GIF 实验，ANN-training Stage A 按下列规则二选一运行：

- `gif.mse_scale_refinement: false`：运行原 Step 5 的 `$CFG_17_P`、`$CFG_8_P`、`$CFG_L_P` Stage A 即可。这些配置与对应 GIF-aware 配置使用相同的 shared Stage A direct min-max GIF qparams；不需要再额外运行 `$CFG_17_G`、`$CFG_8_G`、`$CFG_L_G` 的 Stage A。
- `gif.mse_scale_refinement: true`：运行下文的独立 `$CFG_*_G_MSE` Stage A。该路径与 direct 共享工件隔离，并在同一命令内自动执行 Pass 1 与 MSE Pass 2；不需要、也不应先运行 direct Stage A。

无论选择哪一个 Stage A 分支，若随后训练 `gif_aware` ANN，仍应使用该训练配置执行一次 Step 5 的 Stage B，以生成对应的 common Clip profile。

### Step 5.2：Direct / MSE 必须保持为两条完整且互不混用的实验链

一旦为某个 `gif_aware` 实验建立独立的 MSE 配置（例如 `$CFG_L_G_MSE`），**从 ANN-training calibration 开始直到最终 SNN conversion / evaluation，都必须持续使用同一个配置分支，不能在中途切回 direct 配置**。因此，`$CFG_L_G_DIRECT` 与 `$CFG_L_G_MSE` 不是只在 Step 5.1 calibration 阶段不同，而是两条完整、独立的实验链：

```text
Direct 分支：
CFG_L_G_DIRECT
    → ANN-training direct Stage A
    → direct Stage B
    → GIF-aware ANN fine-tuning
    → Final ANN checkpoint / Final ANN evaluation
    → Post-finetuning Prefix
    → Post-finetuning direct Stage A
    → SNN conversion
    → SNN evaluation

MSE 分支：
CFG_L_G_MSE
    → ANN-training MSE Stage A
    → MSE 对应 Stage B
    → GIF-aware ANN fine-tuning
    → Final ANN checkpoint / Final ANN evaluation
    → Post-finetuning Prefix
    → Post-finetuning MSE Stage A
    → SNN conversion
    → SNN evaluation
```

因此，MSE 分支中以下所有后续命令都必须继续传入：

```bash
--config "$CFG_L_G_MSE"
```

而不能重新使用：

```bash
--config "$CFG_L_G_DIRECT"
```

例如，MSE 分支的 ANN fine-tuning 必须是：

```bash
torchrun \
  --standalone \
  --nproc_per_node="$NGPU" \
  scripts/train_ann.py \
  --config "$CFG_L_G_MSE"
```

对应 Final ANN evaluation 也继续使用 MSE 配置：

```bash
accelerate launch --num_processes 1 \
  scripts/evaluate_lm_harness.py \
  --config "$CFG_L_G_MSE" \
  --neuron ann
```

若 `conversion.use_post_finetuning_artifacts: true`，则 MSE-trained final ANN checkpoint 后续生成 Post-finetuning Prefix 和 Post-finetuning Stage A 时也必须使用 `$CFG_L_G_MSE`：

```bash
python scripts/discover_prefix.py \
  --config "$CFG_L_G_MSE" \
  --stage post_finetuning

python scripts/calibrate_sites.py \
  --config "$CFG_L_G_MSE" \
  --stage post_finetuning \
  --calibration-phase A
```

最终 SNN conversion / evaluation 同样属于该 MSE 分支，例如 GIF SNN：

```bash
python scripts/convert_snn.py \
  --config "$CFG_L_G_MSE" \
  --neuron gif

accelerate launch --num_processes 1 \
  scripts/evaluate_lm_harness.py \
  --config "$CFG_L_G_MSE" \
  --neuron gif
```

若 `conversion.use_post_finetuning_artifacts: false`，SNN conversion / evaluation 会读取该 run 对应的 ANN-training Stage A；对于 MSE 分支，这仍然必须是由 `$CFG_L_G_MSE` 生成的 MSE Stage A。若 selector 为 `true`，则读取 `$CFG_L_G_MSE` 对应 final ANN checkpoint 重新生成的 Post-finetuning Prefix + MSE Post-finetuning Stage A。**无论 selector 为 true 还是 false，都不能在 MSE-trained run 的 SNN conversion / evaluation 阶段切换到 `$CFG_L_G_DIRECT`。**

同理，不允许反向混用：

```text
CFG_L_G_MSE 生成 Stage A
    → CFG_L_G_DIRECT 训练 ANN                         ×

CFG_L_G_MSE 训练 Final ANN
    → CFG_L_G_DIRECT 做 Post-finetuning calibration  ×

CFG_L_G_MSE 训练 Final ANN
    → CFG_L_G_DIRECT 做 SNN conversion/evaluation    ×

CFG_L_G_DIRECT 训练 Final ANN
    → CFG_L_G_MSE 的 MSE artifact 做 conversion      ×
```

Direct 与 MSE 分支的 calibration artifact、ANN run root、checkpoint、Post-finetuning artifact、conversion provenance 和 SNN 输出路径都属于各自独立的 run identity。MSE path 中还包含：

```text
gif_qparams_mse_refined_v1_<config-hash>
```

用于与 direct-min-max artifact 隔离。

> **执行原则：Direct / MSE 一旦分叉，后续所有依赖该 run identity 的步骤都沿各自配置继续向下执行，不再交叉。**

另外，前面定义的 `ALL_CFGS` / `TULU_CFGS` 默认只包含 generated direct 配置，并不会自动包含手工复制得到的 `$CFG_L_G_MSE`。因此 Step 6–10 中针对 MSE 对照分支的命令需要额外以 `$CFG_L_G_MSE` 单独执行，不能认为已有 `for CFG in "${ALL_CFGS[@]}"` 循环会自动覆盖 MSE 实验。


## Step 6：训练 12 个 ANN checkpoint

示例使用两张 GPU。每个配置的训练根目录包含 `ann_training.prefix_enabled` 对应后缀：

```bash
export CUDA_VISIBLE_DEVICES=5,7
NGPU=2

for CFG in "${ALL_CFGS[@]}"; do
  torchrun \
    --standalone \
    --nproc_per_node="$NGPU" \
    scripts/train_ann.py \
    --config "$CFG"
done
```

对于 TL;DR 由 `tldr_train_samples` 指定训练样本数量。训练步数应由实际选中的样本数、GPU 数、batch size、gradient accumulation 和 epoch 共同决定。

Aware ANN forward 语义为：clip-eligible sites 上 `phase_aware + true -> Clip(Phase(x))`、`gif_aware + true -> Clip(GIF(x))`，关闭开关时只执行对应 replacement；Site 5 不论开关均只执行 Phase 或严格 SpikeLLM `n_bits=16` sentinel identity GIF，不执行 Clip。两种路径仍是局部 replacement 后立即聚合的 ANN fine-tuning，不引入跨层时间维度。

## Step 7：为每个 final ANN checkpoint 生成 Post-finetuning Prefix

对于额外的 MSE `gif_aware` 分支，必须对 `$CFG_L_G_MSE` 单独执行本 Step；不能使用 `$CFG_L_G_DIRECT` 去处理 MSE-trained final checkpoint。

四种 mode 都从各自 final ANN checkpoint 生成自己的 Post-finetuning Prefix，彼此不共享；脚本不再拒绝 aware mode。`vanilla` 的 final ANN evaluation 始终不加载这个 Prefix；unaware 的 Final ANN evaluation 仍按 `evaluation.prefix_enabled` 使用 Post-finetuning Prefix，aware 的 Final ANN evaluation 仍使用 Pre-finetuning Prefix。Post-finetuning Prefix 在 SNN selector 为 `true` 时用于 conversion 与 SNN evaluation。对全部 12 个 checkpoint 执行：

```bash
for CFG in "${ALL_CFGS[@]}"; do
  python scripts/discover_prefix.py \
    --config "$CFG" \
    --stage post_finetuning
done
```

## Step 8：生成 Post-finetuning conversion Stage A

对于额外的 MSE `gif_aware` 分支，必须继续使用 `$CFG_L_G_MSE` 生成 Post-finetuning Stage A，使其与 MSE-trained checkpoint、MSE Post-finetuning Prefix 和后续 SNN conversion 保持同一 run identity。

四种 mode 的 final ANN 都独立重新校准。该阶段输出 T/K-independent Stage A，且不生成 Clip profile；aware 的 Post-finetuning 工件保存在各自 run 的 `post_finetuning` 下，不进入 `_shared`。Tulu-3 concrete run 根目录使用 `experiment_seed_<E>_train_seed_<S>_train_samples_<N>_calibration_seed_<C>`，例如 `experiment_seed_42_train_seed_42_train_samples_10000_calibration_seed_42/post_finetuning`：

```bash
for CFG in "${ALL_CFGS[@]}"; do
  python scripts/calibrate_sites.py \
    --config "$CFG" \
    --stage post_finetuning \
    --calibration-phase A
done
```

Post-finetuning 禁止运行阶段 B。Step 7/8 可与 Step 4/5 同时存在且互不覆盖。

## Final ANN mode-aware forward 语义

12 个 final checkpoint 的 `--neuron ann` 统一表示 non-temporal final ANN evaluation，但实际 activation forward 由 `ann_mode` 决定：

| `ann_mode`    | ANN training                                                 | final `--neuron ann`                                         |
| ------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `vanilla`     | identity                                                     | identity                                                     |
| `unaware`     | identity（保留 Rotation/Prefix）                             | identity（保留 Rotation/Prefix）                             |
| `phase_aware` | `PhaseSurrogate.forward()` + optional common Clip            | 同一 ANN-training states 与相同 Clip 设置的 `PhaseSurrogate.forward()` |
| `gif_aware`   | Site 1/7 role-aware `StaticGIF`、Site 2 `AllLowStaticGIF`、Site 5/8/9 identity、Site 3/4/6/10 `StaticGIF` + mode-aware optional Clip | 同一 ANN-training states 与相同 Clip 设置的 static GIF forward |

Aware static surrogate 的时间动态只存在于 site 内并立即聚合，T 不跨 Transformer layer，因此仍属于 ANN。Base 与 rotated-pre-finetuning diagnostic 保持 identity。

## Step 9：评估 12 个 final ANN checkpoint

MSE `gif_aware` 对照分支的 Final ANN evaluation 需要额外用 `$CFG_L_G_MSE` 单独执行；不要用 `$CFG_L_G_DIRECT` 去评估 MSE-trained checkpoint。

`vanilla` 的 final ANN evaluation 固定不加载 Prefix，即使已有 Post-finetuning Prefix 工件。`unaware` 的 final ANN evaluation 是否加载 Post-finetuning Prefix 由 `evaluation.prefix_enabled` 决定；aware 则按同一开关从 Pre-finetuning 目录读取 Prefix。`conversion.use_post_finetuning_artifacts` 不影响 Step 9。结果目录按实际是否加载 Prefix 隔离。

TL;DR：

```bash
export CUDA_VISIBLE_DEVICES=0

for CFG in "${TLDR_CFGS[@]}"; do
  accelerate launch --num_processes 1 \
    scripts/evaluate_tldr.py \
    --config "$CFG" \
    --neuron ann
done
```

Tulu 3 / lm-eval：

```bash
for CFG in "${TULU_CFGS[@]}"; do
  accelerate launch --num_processes 1 \
    scripts/evaluate_lm_harness.py \
    --config "$CFG" \
    --neuron ann
done
```

## Step 10：创建 SNN conversion descriptor 并执行 SNN evaluation

MSE `gif_aware` 分支的 SNN conversion 与 SNN evaluation 必须继续传入 `$CFG_L_G_MSE`。无论 `conversion.use_post_finetuning_artifacts` 为 `true` 还是 `false`，都不得在这一阶段切回 `$CFG_L_G_DIRECT`；selector 只选择该同一配置分支内的 Pre/Post Stage A 来源，不会把 MSE run 转换成 direct run。

Step 10 与 Step 9 的 static ANN semantics 不同：无论 checkpoint 的 `ann_mode` 是什么，`--neuron phase|gif|mtn` 都分别进入 `deploy_phase|deploy_gif|deploy_mtn` full-temporal SNN，且不使用 common Clip。

SNN source 由 `conversion.use_post_finetuning_artifacts` 唯一决定：`true` 时四种 mode 都使用 Step 7 Post-finetuning Prefix + Step 8 Stage A；`false` 时 unaware/phase-aware/gif-aware 使用 Step 4 Pre-finetuning Prefix + Step 5 shared Stage A，vanilla 为非法。切换 selector 不重新训练 ANN，也不重跑 Step 4/5/7/8；只重跑 conversion 与 SNN evaluation。两个 selector 的输出分别位于 `snn/use_post_finetuning_artifacts_true/` 与 `snn/use_post_finetuning_artifacts_false/`。每个 run 分别创建 phase、gif、mtn 三种 descriptor。

Phase conversion 只读取 Phase state，GIF conversion 只读取 GIF state，MTN conversion 只读取 MTN state。三种 SNN deployment 都不加载或执行任何额外 Clip；GIF `_quantize()` 内部的 `qmin/qmax` clamp 属于 GIF 编码算法自身，必须继续保留：

```bash
for CFG in "${ALL_CFGS[@]}"; do
  for NEURON in phase gif mtn; do
    python scripts/convert_snn.py \
      --config "$CFG" \
      --neuron "$NEURON"
  done
done
```

如果部署参数不同于 ANN 训练配置，不要改动源配置中的 run identity；使用部署 override。Layout 会先固定源 ANN run，再只改变运行时参数与 SNN 子目录：

```bash
python scripts/convert_snn.py --config "$CFG" --neuron phase --phase-T 8
python scripts/convert_snn.py --config "$CFG" --neuron mtn --mtn-T 8 --mtn-K 12

accelerate launch --num_processes 1 scripts/evaluate_tldr.py \
  --config "$CFG" --neuron phase --phase-T 8
accelerate launch --num_processes 1 scripts/evaluate_tldr.py \
  --config "$CFG" --neuron mtn --mtn-T 8 --mtn-K 12

python scripts/verify_artifacts.py --config "$CFG" \
  --phase-T 8 --mtn-T 8 --mtn-K 12
```

SNN evaluation 是否实际注入 Prefix 仍由 `evaluation.prefix_enabled` 决定；selector 只决定它从哪一套 Prefix/Stage A 工件读取，且 conversion metadata、metrics 与 verify 都记录同一个 selector。

## Step 11：Energy profiling of final deployment models

Energy profiling 只统计最终实际部署 graph。每个 model/task 的正式 Energy Table 固定四行：vanilla Final ANN checkpoint 的 ordinary dense ANN，以及**同一个**最终选定 aware Final ANN checkpoint 分别转换得到的 Phase、GIF、MTN full-temporal SNN。`unaware` 和未选中的 aware checkpoint 仍参与 Step 9/10 性能实验，但不参与正式 Energy Table。

每个模型的 selected-aware checkpoint 必须由最终性能结果在 `phase_aware` / `gif_aware` 中二选一。运行前在当前 shell 显式设置下面三个变量；注释中的赋值仅展示可选写法，不代表项目已作最终选择：

```bash
# 任选每组中的一个，在运行前取消注释或自行赋值：
# ENERGY_CFG_17_SNN="$CFG_17_P"    # 或 "$CFG_17_G"
# ENERGY_CFG_8_SNN="$CFG_8_P"      # 或 "$CFG_8_G"
# ENERGY_CFG_L_SNN="$CFG_L_P"      # 或 "$CFG_L_G" / "$CFG_L_G_MSE"

: "${ENERGY_CFG_17_SNN:?先选择 Qwen3-1.7B 的 phase_aware 或 gif_aware config}"
: "${ENERGY_CFG_8_SNN:?先选择 Qwen3-8B 的 phase_aware 或 gif_aware config}"
: "${ENERGY_CFG_L_SNN:?先选择 Llama-3-8B 的 phase_aware 或 gif_aware config}"
```

若选定 Llama GIF-aware MSE-refined 分支，`ENERGY_CFG_L_SNN` 必须指向同一 `$CFG_L_G_MSE`，不能在 Energy 阶段切回 direct 配置。三个 selected-aware config 都必须已有对应的 Phase、GIF、MTN conversion descriptors。Phase/MTN 的 `--phase-T`、`--phase-base`、`--mtn-T`、`--mtn-K` 部署覆盖参数仍可使用，但必须与相应 descriptor 一致。

```bash
# Qwen3-1.7B
python scripts/profile_energy.py --config "$CFG_17_V" --neuron ann
for NEURON in phase gif mtn; do
  python scripts/profile_energy.py --config "$ENERGY_CFG_17_SNN" --neuron "$NEURON"
done

# Qwen3-8B
python scripts/profile_energy.py --config "$CFG_8_V" --neuron ann
for NEURON in phase gif mtn; do
  python scripts/profile_energy.py --config "$ENERGY_CFG_8_SNN" --neuron "$NEURON"
done

# Llama-3-8B / Tulu-3
python scripts/profile_energy.py --config "$CFG_L_V" --neuron ann
for NEURON in phase gif mtn; do
  python scripts/profile_energy.py --config "$ENERGY_CFG_L_SNN" --neuron "$NEURON"
done
```

汇总正式 Energy Table 前，检查每个模型的三份 SNN `energy_metadata.json`：`checkpoint_source`、`source_ann_mode` 和 `experiment_id` 必须一致。ANN baseline 的 checkpoint 本来就不同于 SNN，不要求四行 checkpoint 相同。`profile_energy.py` 会拒绝非 vanilla 的 ANN Energy，以及非 aware checkpoint 的 SNN Energy；Step 9/10 的 evaluation 和 conversion 能力不受此限制。

### Prefix provenance

Prefix provenance 分三层记录：`configured_evaluation_prefix_enabled` 是 YAML 的 `evaluation.prefix_enabled`；`resolved_prefix_policy_enabled` 是 Final ANN/SNN 协议解析后的 Prefix 策略；`actual_evaluation_prefix_enabled` 与 `prefix_cache_loaded` 表示本次 forward 是否真正注入非空 KV cache。`energy_path_prefix_enabled` 始终等于 resolved policy，路径代表实验协议 identity，不代表 cache 是否非空。vanilla ANN 即使 YAML 开关为 `true`，resolved policy 仍为 `false`，cache 未加载、`prefix_artifact_stage=null`、`prefix_length=0`。

当 resolved policy 为 `true`、但 Prefix discovery 得到空 `prefix_token_ids` 时，可能不存在 KV cache；这是合法的 empty Prefix。该 run 仍保存在 Prefix-enabled 路径下，`prefix_cache_loaded=false`、`actual_evaluation_prefix_enabled=false`、`prefix_length=0`，而 `prefix_artifact_stage` 仍记录被解析的 Pre/Post Prefix stage。只要 cache 未加载，length 必须为 0；已加载 cache 时 length 必须为正。当前 metadata schema 为 v3，旧 schema v2 的 `actual_evaluation_prefix_enabled` 表示 resolved policy，正式论文结果建议重新运行以避免语义混淆。

### 四行 profiling 样本身份

汇总每个模型的 ANN、Phase、GIF、MTN 四行正式 Energy Table 前，必须核对四份 `energy_metadata.json` 的 `validation_manifest_sha256`、`selected_validation_positions`、`profile_num_samples`、`profile_seed`、`profile_sequence_length` **全部相同**。即使四行都来自同一 model/task，也不能省略此检查：calibration sample-count 或 seed sweep 可能使 ANN 与 SNN 使用不同的 held-out 样本。三种 SNN 还必须保持 `checkpoint_source`、`source_ann_mode` 和 `experiment_id` 一致。

`calibration.num_samples` 控制 Energy profiling 样本数；profiling 从 held-out validation manifest 抽样，不复用 Stage-A training calibration rows。每条完整样本固定为 512 tokens，结果是 per-sequence mean。结果写入 `<vanilla-run>/energy/ann/<resolved-prefix-policy>/profile_num_samples_<N>/`，或 selected-aware run 下镜像 SNN deployment identity 的 `energy/snn/.../<resolved-prefix-policy>/profile_num_samples_<N>/`。Prefix 路径沿用已有 `prefix_enabled_dirname()` 命名。Energy 只覆盖理论计算运算，不包含内存与整机能耗。旧 v1/v2 或非最终选定 checkpoint 的 Energy 结果不得作为正式表格数据，需按当前 v3 protocol 重新运行。

## 附录 A：整体依赖顺序

实验依赖关系是：

```text
固定数据 manifest
├── Base baseline（无 Rotation / Prefix / calibration）
├── Vanilla
│   └── ANN training
│       └── Final ANN
│           ├── Step 7 Post-finetuning Prefix
│           ├── Step 8 Post-finetuning Stage A
│           └── SNN conversion / evaluation（selector 必须 true）
└── Rotated modes（unaware / phase_aware / gif_aware）
    └── Rotation
        ├── Step 4 shared Pre-finetuning Prefix
        ├── Step 5 shared ANN-training Stage A
        │   └── phase/gif aware 另生成 Stage B 供 ANN fine-tuning
        └── ANN training
            └── Final ANN
                ├── Step 7 per-run Post-finetuning Prefix
                ├── Step 8 per-run Post-finetuning Stage A
                └── SNN conversion / evaluation
                    ├── selector=false：Step 4 + Step 5 Stage A
                    └── selector=true：Step 7 + Step 8
```

两套 artifacts 可以同时存在。切换 selector 不重新训练 ANN，也不重新生成已经存在的另一套 artifacts；只需重新 convert / evaluate SNN。

Base baseline 被放在数据 manifest 之后、所有 Rotation/Prefix/calibration 操作之前，是为了明确它只衡量原始 pretrained Base。Rotation 后、ANN 微调前 evaluation 紧随 Rotation 和共享 Prefix 的准备，用于隔离观察 Rotation 与 Prefix 本身的影响。

## 附录 B：Prefix 开关与 SNN artifact source selector 的边界

| 配置键                                     | 控制对象                                                     | Prefix 来源                                              | 影响的输出路径                             |
| ------------------------------------------ | ------------------------------------------------------------ | -------------------------------------------------------- | ------------------------------------------ |
| `ann_training.prefix_enabled`              | ANN training；ANN-training calibration                       | Pre-finetuning Prefix                                    | run 根目录；ANN-training calibration       |
| `rotated_pre_finetuning.prefix_enabled`    | Rotation 后、ANN 微调前 evaluation                           | Pre-finetuning Prefix                                    | rotated pre-finetuning evaluation          |
| `post_finetuning.prefix_enabled`           | 四种 mode 的 Post-finetuning calibration 是否使用 Prefix     | Post-finetuning Prefix                                   | 各 run 的 post-finetuning calibration      |
| `conversion.use_post_finetuning_artifacts` | 仅 SNN conversion/evaluation 的 artifact source              | `true`=Post bundle；`false`=shared Pre bundle            | `snn/use_post_finetuning_artifacts_<bool>` |
| `evaluation.prefix_enabled`                | unaware/aware 的 Final ANN evaluation；所有模式的 SNN evaluation | Final ANN：aware=Pre、unaware=Post；SNN 由 selector 决定 | final ANN/SNN evaluation                   |

这些开关受 mode protocol 约束，并非四种 mode 都能自由组合：

| 配置                                       |                                         vanilla |           unaware |       phase_aware |         gif_aware |
| ------------------------------------------ | ----------------------------------------------: | ----------------: | ----------------: | ----------------: |
| `ann_training.prefix_enabled`              |                                      强制 false |         强制 true |         强制 true |         强制 true |
| `rotated_pre_finetuning.prefix_enabled`    |                                        无此流程 | 可独立 true/false | 可独立 true/false | 可独立 true/false |
| `post_finetuning.prefix_enabled`           |                                   可 true/false |     可 true/false |     可 true/false |     可 true/false |
| `conversion.use_post_finetuning_artifacts` |                                         仅 true |        true/false |        true/false |        true/false |
| `evaluation.prefix_enabled`                | 可 true/false（仅影响 SNN；final ANN 强制关闭） |     可 true/false |     可 true/false |     可 true/false |

`ann_training.prefix_enabled` 不是自由 ablation 参数；vanilla 固定为 false，所有 rotated modes 固定为 true。阶段适用范围内的 evaluation / post-finetuning 开关可以独立控制。例如：

- `post_finetuning.prefix_enabled=false`、`evaluation.prefix_enabled=true`：conversion calibration 不带 Prefix；unaware/aware 的 final ANN 与各模式的 SNN evaluation 按其各自 Prefix 来源加载 Prefix，vanilla final ANN 仍不加载。
- `evaluation.prefix_enabled=false` 时，评估代码忽略已有 Prefix 工件，并把结果写入 `prefix_enabled_false`。

目录中的 `prefix_enabled_ture` 是项目已有且需保持兼容的拼写，不应手工改成 `prefix_enabled_true`。

## 附录 C：两类 Prefix 的定义与生成时间

### C.1 Pre-finetuning Prefix

Pre-finetuning Prefix 只存在于 unaware、phase-aware、gif-aware，在 Rotation 完成后从同一个 rotated fused Base、使用与 Rotation regression 相同的 fixed canonical 128 发现；它按 model-task + `experiment.seed` 共享，不随 data-selection identity 分叉。它服务于：

- ANN training；
- ANN-training calibration；
- Rotation 后、ANN 微调前 evaluation。

旧实现中的 `ann_training_prefix` 和 `rotated_pre_finetuning/prefix` 实际来源相同，现在已经合并为同一个对象。TL;DR 与 Tulu-3 都使用：

```text
.../_shared/seed42/rotated_prefix/
└── pre_finetuning_prefix/
    └── num_samples_128/
        ├── prefix_state.json
        └── prefixed_key_values.pt    # prefix_token_ids 非空时存在
```

发现命令统一为：

```bash
python scripts/discover_prefix.py --config CONFIG --stage pre_finetuning
```

`--stage ann_training` 与 `--stage rotated_pre_finetuning` 仍作为兼容别名接受，但都会写入同一 canonical 目录；新实验只使用 `--stage pre_finetuning`。

### C.2 Post-finetuning Prefix

Post-finetuning Prefix 为四种 mode 在 ANN training 完成后从各自 `ann/final` 发现。它服务于：

- Post-finetuning conversion calibration；
- unaware 的 final ANN checkpoint evaluation（受 `evaluation.prefix_enabled` 控制）；aware 的 Final ANN evaluation 仍使用 Pre-finetuning Prefix；
- SNN conversion 与 SNN evaluation。对于 vanilla，它不参与 final ANN evaluation，实际供后续 SNN conversion / SNN evaluation 使用。

该 Prefix 不跨 run 共享。它在 selector 为 `true` 时服务全部 mode 的 SNN conversion/evaluation；selector 为 `false` 时 non-vanilla SNN 复用共享训练前 Prefix。

`prefix_state.json` 中：

- `prefix_token_ids` 是实际 Prefix token ID；
- `prefix_text` 是 tokenizer 对这些 ID 的 decode 结果；
- `prefix_token_ids: [29038]` 且 `prefix_text: "SUB"` 表示该 tokenizer 将 token 29038 decode 为 `SUB`；
- 非空 Prefix 还要求存在固定的 `prefixed_key_values.pt`。

## 附录 D：Calibration A/B 的定义与生成时间

### D.1 Vanilla analysis

原始 pretrained Base 的分析性统计；执行时只运行 `--calibration-phase A`，不用于训练或 SNN conversion。

### D.2 ANN-training Stage A

服务 phase-aware / gif-aware ANN training；同一份 shared Stage A 也可在 selector 为 `false` 时服务 unaware/phase-aware/gif-aware 的 SNN conversion。Stage A 从 rotated fused Base 收集 statistics，并生成与 Phase/MTN runtime sweep 无关的 `phase_state.pt`、`gif_state.pt`、`mtn_state.pt`。当 `gif.mse_scale_refinement=false` 时只执行原有 statistics/direct-min-max state；为 `true` 时同一 Stage A 自动追加 fixed-bin histogram Pass 2，并在写入 `gif_state.pt` 前完成 offline static-MSE qparam 搜索。目录由 `group_size`、`num_samples`、MSE 开关与 MSE config signature 共同隔离，site 目录内不得出现 `clip_state.pt`。

### D.3 ANN-training Stage B

Stage B 不加载模型或数据，只读取 Stage A，为当前 `phase.T`、`mtn.T` 生成独立 Clip profile。Site 1 使用 q/k/v role-specific Clip，Site 7 使用 gate/up role-specific Clip，Site 5 永久无 Clip。训练无论 `common_clip_enabled` 为 true 或 false 都校验并记录所选 profile。

### D.4 Post-finetuning Stage A

为四种 mode 的 final ANN checkpoint 生成。完成各自 Post-finetuning Prefix 后运行 A；selector 为 `true` 时供三类 SNN conversion 共用；不运行 B。

当前 Qwen3-1.7B、LR=1e-7 诊断结论：

- 修复前第一个 `>1e-2` 节点为 `layer_000/site_01/post`；
- 对齐 Qwen/Llama BF16 RMSNorm cast 顺序后，Site 1 pre/post 均为零，首点后移到 Site 2；
- 当前首个非零点是 Layer 0 q/k/v projection 的 BF16 分帧线性求和（约 `2.5e-3`），q_norm、RoPE、R3 继续累积后在 Site 2/3 被 Phase 阈值放大；FP32 primitive 未失败，因此没有改动这些算法路径；
- final RMSNorm Phase bypass 未显著缩小 P vs S，因此当前证据不支持先修改 global final Phase topology。

Regression 工具与诊断修正不改变 Phase 参数、τ、Prefix、训练 LR、T、base 或 Site 数量；未被 first-divergence 证实的算子不得为追求 ROUGE 而修改。

## 附录 I：随机种子与训练/Calibration 数据抽样关系

| 参数 | 任务 | 作用 |
| --- | --- | --- |
| `experiment.seed` | TL;DR / Tulu-3 | Python/NumPy/PyTorch/CUDA 全局随机性、Hugging Face Trainer `seed/data_seed`、fixed canonical 128；同时决定 Tulu-3 validation/shared-pool split。 |

当前默认配置下，TL;DR 与 Tulu-3 的 **Stage-A calibration selection** 都是嵌套抽样：先按任务对应的 training subset seed 选取 10000 条 ANN training samples，再从这 10000 条按 `calibration.seed` 选取 128 条 Stage-A calibration samples；所以 Stage-A calibration 必然是 ANN training subset 的子集。这个 128 不包括独立用于 rotation regression 的 `canonical_preprocessing_calibration` 128 samples。

```text
TL;DR: raw train → tldr_train_seed → ANN train 10000 → calibration.seed → Stage-A calibration 128
Tulu-3: raw train → experiment.seed → validation/shared pool → train_seed → ANN train 10000 → calibration.seed → Stage-A calibration 128
```

完整 data-selection identity 只用于 concrete run 和 Stage-A data-dependent shared artifacts。`canonical_preprocessing_calibration` 只依赖 dataset identity 与 `experiment.seed`；Rotation weights、Rotation regression、Pre-finetuning Prefix 和 rotated-pre-finetuning evaluation 均按 experiment/model-policy 共享。Tulu-3 concrete ANN run 示例：`experiment_seed_42_train_seed_42_train_samples_10000_calibration_seed_42`；TL;DR 示例：`experiment_seed_42_tldr_train_seed_42_train_samples_10000_calibration_seed_42`。新路径与旧 shared artifacts 不兼容：应从 Step 2 重建 canonical manifest，再执行一次 Rotation 与 Pre Prefix；各 data-selection identity 的 Stage A/B、ANN checkpoint、Post 与 SNN artifact 仍需独立生成。


Tulu-3 lm-eval 的每个 enabled benchmark 独立保存到 `evaluation/.../task_results/<task>/<spec>/` 下的 `results.json` 与 `test_selection.json`，并只记录该 benchmark 自身的 execution counter。每个 evaluation root 写入只含 `task_times` 和 `task_metrics` 的 `evaluation_summary.json`；task time 使用 lm-eval wall time，metric 保持 lm-eval 原始 canonical 数值，不计算 overall score。`verify_artifacts.py` 会对 Final ANN 和 Phase/GIF/MTN SNN 的每个 benchmark 分别校验 task spec、pinned lm-eval revision、CoT semantic、test seed、selection、selected count、effective sample count 与 summary。


`metric` 与 `cot` 都是项目对 pinned lm-eval task 定义的强校验字段，不传给 `simple_evaluate()`。每个 selection 还保存 leaf population；verify 会确定性重放抽样，并比较 ANN、Phase、GIF、MTN SNN 的逐 document selection 是否完全一致。
